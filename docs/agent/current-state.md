# Current state

Updated 2026-09-09. The repository now has a playable first-pass duck-flight prototype rather than placeholder-primitives-only motion.

The BirdFlight scene contains a low-poly stylized mallard imported from `DuckV1.blend` through the checked-in FBX pipeline. It has 4 skinned renderers, 4,450 imported vertices / 6,000 triangles, one opaque vertex-color material and a 9-bone root/left/right wing rig. Analytic two-link IK maps each controller through shoulder, forearm, hand and tip; calibrated local target smoothing follows a moving/turning bird without world-space lag. First person hides face/neck geometry while preserving torso/wing context. Measured ground posts provide speed/scale reference.

XR calibration captures the first valid HMD origin at physical 1:1 scale, then requires a deliberate right-primary press with tracked head/hands and 0.7-2.2 m spread. Arm offsets scale from human span to the 1.12 m duck rig on all axes. Wing input/presentation stays neutral until capture succeeds; a camera-relative 3D prompt gives the required action. Tracking loss contributes no flap, preserves the last head pose and eases the rig toward rest; reacquisition suppresses its first derivative.

Flight is a deterministic persistent point mass. Gravity, airspeed-squared lift/drag, banked lift, stall degradation, tuck area reduction, flare incidence/drag and oriented per-wing stroke reaction integrate velocity in bounded substeps. Perching remains, with simple ground contact and flap takeoff. Wind, angular momentum, general collision, ground effect and per-feather airflow are not modeled. Duck profile constants are gameplay tuning rather than biological claims.

Validated locally with Unity 6000.6.0f1 and Blender 5.2.1 LTS: 33/33 EditMode and 5/5 PlayMode tests pass; repository structural checks inspect 297 files; 12 host Python tests pass; static and rigged Blender smoke tests pass, including source preservation, meter-scale FBX roundtrip, invalid-skin rejection and actual hand-bone deformation. Three independent quality rounds closed all blocker/high desktop/source findings. Assessed final dimensions are 8-9/10 except subjective 7/10 toy-like proportions/wing silhouette.

Android Build Support, SDK/NDK and OpenJDK are installed. A Unity development Android build succeeds to `builds/quest/VoarVR.apk`; exact final artifact details are in the 2026-09-09 handoff. Android uses GameActivity, Vulkan, ARM64, IL2CPP, single-pass instancing and OpenXR input-polling latency priority. No adb device is currently connected, so install, launch, stereo rendering, tracked startup/calibration/recenter/dropout, physical alignment, comfort and device performance remain unverified.

Repository hygiene has one known boundary: 45 generated Android CMake/Ninja files under `unity/.utmp/` are tracked from earlier work. `/unity/.utmp/` is now ignored, and the successful builds' changes to those files were restored, but removing the tracked files still requires explicit user approval because automated approval review rejected deletion. Nothing was committed or pushed.

A second species and a character-select screen exist as of the same day (see [character-select handoff](session-handoffs/2026-09-09-character-select-v1.md)). `BirdCharacterDefinition` is a ScriptableObject stat card (Size, Speed, Power, Agility, Weight, each 0.3-3 or 0-1) that bakes into a `BirdFlightProfile` via `BuildProfile()`; the Duck baseline is every stat at its midpoint. `Assets/Resources/Characters/{Duck,Dragon}.asset` are the two entries today. `BirdFlightDriver.Start()` resolves `CharacterSelection.Chosen` (falling back to Duck, then clearing it so a later direct scene load never inherits a stale pick), instantiates that character's rig model, and rewires `BirdRigDriver` by the same bone-name contract every rig exports under (`Left/RightUpper/Forearm/Hand/Tip`, a `"*Face"` renderer) - this is the same contract `blender/scripts/create_duck.py` and the new `create_dragon.py` both produce, so a new species is a Blender script plus one `.asset` away. `CharacterSelectController` builds its own uGUI Canvas at runtime from every definition under `Resources/Characters`, so the select screen needs no scene-authored UI. Bootstrap now routes through `CharacterSelect` before `BirdFlight`. `DragonV1.blend`/`Dragon.fbx` were generated and verified headless (nine-bone rig, FBX roundtrip, hand-bone deformation, ~2.9 m wingspan) but not yet inspected inside the Unity Editor - `VoarVR/Configure Characters` must be run once to populate each definition's `RigModel` reference before Play mode or the test suite will work.
